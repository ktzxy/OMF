# 实例信息总览（`omf info`）

> 用途：**生产排障 / 部署验证 / 交接** 的第一入口。一条命令集中展示最关心的环境信息，无需逐个 `cat` 配置或连库查询。

## 命令

```bash
omf info
```

## 输出内容

`omf info` 分 6 段展示：

| 段落 | 内容 | 适用场景 |
|------|------|---------|
| **主机与网络** | 主机名 / 操作系统 / 主机 IP / 当前用户 | 确认在正确的机器/用户下操作；多机（主备）场景确认当前节点 |
| **Oracle 路径** | `ORACLE_HOME`/`ORACLE_BASE`/`ORACLE_SID`/数据目录/备份目录/`TNS_ADMIN`/Alert 日志/监听器日志/SPFILE | 排障时快速定位各日志与配置路径；交接时告知新运维关键路径 |
| **监听器** | 运行状态 / 监听端口 / 监听 HOST | 确认监听端口与配置是否一致（`omf listener port` 后验证）|
| **实例与数据库** | 实例名/版本/状态、库名/open_mode/database_role/归档模式、服务名、归档目标 | 确认实例角色（主/备）、归档是否开启（备份前置）|
| **PDB 连接串** | 各 PDB 的 **EZCONNECT 连接串**（`//IP:端口/PDB`）+ open_mode | **应用连接/交接**最常用：直接复制给应用或同事 |
| **内存概要** | `SGA_TARGET`/`PGA_AGGREGATE_TARGET`/SGA 当前使用/系统大页（总/空闲）| 确认内存规划是否符合预期（`omf tune memory` 的参考）|

## 使用建议

- **排障第一步**：`omf info` 快速确认节点、角色、端口、日志路径，再结合 `omf log errors` / `omf check all` 深入。
- **交接/新人上手**：`omf info` 的输出就是一套"环境速查卡"，避免新人四处翻配置。
- **DG 主备验证**：两台机各跑一次 `omf info`，对比 database_role / IP / 端口，确认主备关系。
- **应用连接串**：多组织场景下，直接取 `omf info` 输出的 PDB EZCONNECT 串改到应用连接配置。

> 提示：`omf info` 是只读命令，可安全在任何环境执行；数据库未运行时相关段显示"未运行/无法连接"，不影响其余信息展示。
